## Причины слабого подтверждения названий

1. **Без `-x` название должно быть подтверждено.** Команда пользователя
   `namer -b` включает это правило. `-b` создаёт журнал восстановления,
   но не разрешает использовать неподтверждённые хинты.
2. **Поиск Wikipedia берёт первый результат из трёх, без контекста фильма
   и года.** Проверенные ответы API: для Baskin первые результаты —
   Baskin-Robbins, Carole Baskin, Baskin; для Dracula — Dracula, Count Dracula,
   Dracula Untold; для Climax — Climax, Climax!, G1 Climax. Страница нужного
   фильма не попадает в этот короткий список.
3. **Год фильма проверяется функцией для сериалов.** `fetch_show_year`
   смотрит страницы season 1, TV series, anime, берёт минимальный год,
   а затем `wikipedia_feed` требует точного совпадения с годом файла.
   В локальном кэше обнаружены Scream → 2015 против файла 1996,
   Wolf Creek → 2016 против 2005, Martin → 1992 против 1977,
   The Crazies → 2010 против 1973, Basket Case → 1994 против 1982.
   Это воспроизводимые конфликты кэша, а не доказательство отсутствия фильма.
4. **Подтверждение и перевод смешаны.** `get_translated_title` может успешно
   проверить тип и год произведения и вернуть то же название. Но
   `enrich_title_via_wiki` возвращает False, если строка не изменилась.
   Поэтому источник остаётся hint, и требуется повторное подтверждение
   через менее точный поиск первого результата.
5. **Другого работающего источника для фильмов нет.** TVmaze сразу возвращает
   входные метаданные для `is_series=False`. TMDB вызывается только с ключом;
   в проверенной среде ключа нет. Фактически фильмы зависят от Wikipedia.
6. **Мусор остаётся в поисковых хинтах.** Реальные примеры:
   Cure → `Cure H 265 iVy`, His House → `His House AC35 1`,
   Martyrs → `Martyrs FRENCH`, Suspiria → `Suspiria EAC3 ITA ENG SARTRE`.
   Сборники Wishmaster и The Hills Have Eyes сохраняют порядковые номера,
   слова Horror, Eng, Rus, Subs и имена режиссёров. Это ухудшает поиск.

- Суффикс статьи `(2013 film)` не удаляется: создано
  `Under the Skin (2013 film) (2013).mkv`. Аналогично Dawn of the Dead
  и Slither. Регулярное выражение удаляет `(film...)`, но не `(YEAR film)`.

  `.tmp.ab-av1-encoding.Black Swan ..._tmp_encode.mkv` и переименовал его
  в `Black swan (2010).mkv`. Основной фильм получил суффикс `_1`.
  Временные файлы следует исключать до идентификации.

## Что требуется исправить

- Разделить результат подтверждения названия и факт изменения строки.
- Для фильмов искать с контекстом типа и года, проверять несколько кандидатов,
  сохранять исходную страницу до чтения её метаданных.
- Проверять год фильма по выбранной сущности, не по страницам сериала;
  учитывать обоснованную разницу фестивального и прокатного года.
- Очищать технические хинты и суффиксы статей, исключать временные файлы.
- Выводить отдельные числа: переименовано, уже имело нужное имя,
  дополнительные материалы, название не подтверждено, ошибки провайдеров.

Запрет на неподтверждённые хинты при этом должен сохраняться.

## Выполненные исправления и проверка

После явного разрешения пользователя проведены сетевые проверки только через
Wikipedia/Wikidata. В повторном проходе старой логики получено 96 ответов
HTTP 429. Эта причина теперь подтверждена: программа отправляла запросы слишком
часто и скрывала ошибки за отсутствием результата.

Исправлены:

- Подтверждение неизменившегося названия, повторное использование выбранной
  сущности и отсутствие повторного поиска уже проверенного результата.
- Поиск с контекстом фильма/сериала и года, перебор кандидатов, исключение
  старых ремейков до ранжирования. Подтверждаются тип, год и название;
  слабого совпадения одного слова недостаточно. Альтернативные названия
  дополнительно сверяются с алиасами Wikidata.
- Использование годов выбранного фильма и всех документированных релизов
  вместо страниц одноимённых сериалов. Учитываются подтипы фильмов.
  Старый общий кэш годов больше не используется для такого подтверждения.
- Ограничение запросов между всеми рабочими потоками, объединение одинаковых
  запросов, повтор после 429/временных HTTP-ошибок с учётом Retry-After,
  отображение ошибки провайдера в причине пропуска. Ошибки не кэшируются
  как постоянное отсутствие произведения.
- Очистка технических токенов, языков, групп релиза, пометок сборников,
  суффиксов статей, исключение временных файлов. Явное название `-t`
  сохраняется при сетевом подтверждении. Год может браться из папки релиза.
- Отдельные счётчики неизменённых файлов, дополнительных материалов,
  неподтверждённых названий, других пропусков и ошибок.
